The Work

Years of research, distilled into small forms that can be tested.

We've done a great deal of work — philosophical, semantic, and technical — mapping how a relational computing ecosystem could actually be built. This page is the honest state of it: our method, our working prototype, and the technical thesis underneath.

Method

Design interventions

We work through design interventions: prototypes deliberately limited in scope, each testing one specific technical thesis — one component of how Seption works. Each form we produce is kept as simple as possible: only what's absolutely necessary to prove or disprove the idea. We learn during and after each one, report the results to the communities we work with, and let the learning shape the next intervention.

This is an Alexandrian process. Rather than specifying a grand system up front and imposing it, we grow the system through a sequence of small, testable steps — each one keeping the whole alive — until the pieces are ready to integrate into a minimum viable form we can iterate on with real communities and their real relationality needs.

Past interventions have tested graph population from everyday sources (Obsidian, Notion, Telegram), nodes as lists of outgoing links, reification and versioning models, and interface patterns for navigating dense semantic structure.

Now

The Seption RDF editor

Our current intervention is a working, local-first research instrument: an editor for building, navigating, and refining knowledge graphs, running entirely in your browser with everything stored on your own machine — there is no server copy of your work.

Many lenses, one graph

Tree, graph, and reader-card views are panes onto the same living structure — expand any relationship, follow any backlink, focus any node.

Full RDF 1.2

Named nodes, literals, blank nodes, named graphs, and RDF-star triple terms, with Turtle, TriG, and JSON-LD import/export and a large vocabulary library built in.

Local-first

Projects persist in your browser's own storage with deep undo and autosave. Early experiments in direct peer-to-peer sharing and an AI agent bridge are already wired in.

The editor is where we are testing the question the whole ecosystem rests on: how should links themselves be represented so that a decentralized graph stays navigable, mergeable, and honest about its own history? Several candidate representations have been modeled inside the editor itself; one has already been retired. That's the method working as intended.

Status, honestly: this is a pre-1.0 research prototype, not a product. It works — we use it — but its purpose is to settle the foundations, not to be the thing you install next week. If you'd like a demo, ask us in Discord (or find us at DWeb Camp).

Thesis

The technical thesis

Underneath the philosophy is a concrete bet about data structures. In brief:

Everything is a node — including relationships

Seption is a monotyped, self-dual hypergraph: every node can act as an edge and every edge is a node. Relationships carry their own metadata — confidence, source, time, authorship — without the infinite regress that has haunted RDF reification. The trick is a duality of representation: every relation exists both as a compact preview inside the nodes it touches (for fast, local traversal) and as a full reified node of its own (the canonical record, with all participants, roles, provenance, and history).

Nodes are computed, not stored

A Seption node is virtual: it is computed from a set of immutable, content-addressed entries — an append-only log of contributions merged by set union, with tombstones cancelling what they name. Two machines that have seen the same entries compute the same node, with zero coordination. That is the CRDT, expressed natively in RDF rather than bolted alongside it: edit history, n-ary relationality, and permissions — features RDF should have had all along.

Meaning from use, not decree

We reject the assumption that interoperability requires everyone to agree on one ontology. Situated use is a better primitive than ontology: categories are tools, not prisons; link types and node types emerge through use. Disagreement is first-class data — preserved with provenance and authorship, never silently merged away. Interoperability comes from shared accountability, not shared meaning.

Standing on the shoulders of the Semantic Web

This lineage runs from the Memex through Xanadu to RDF and Linked Data — and we are extending it rather than abandoning it: staying RDF-compatible while adding what it lacked. Where the Semantic Web optimized for machines exchanging facts, Seption optimizes for humans (and machines) making meaning together — meeting people where they are, providing affordances for actual use, and carrying a set of values in its architecture.

Next

Where this is going

Immediately ahead: settling the link representation, making links fully n-ary, content-addressed node identity, automatic backlink propagation, and the full CRDT operation set — the machinery for offline, concurrent, coordination-free collaboration.

Then outward: we want to build with other projects, not beside them. We're planning lightly-facilitated workshops — Seption interoperability labs — doing design research with aligned indie tools and communities to discover together what a common relational data model needs to be. The solution should be shaped by the needs of all the projects and people involved, not designed by a few and imposed on the many.

We are also looking for sustainable, aligned funding — support that lets this stay free, libre, and open while we do the slow foundational work that product timelines never allow. If that's you, we'd love to talk.
